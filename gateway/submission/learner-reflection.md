# 学员反思

以下依据我的回答整理，代码主要由 Agent 实现，不能据此推断我已独立验证所有生产条件。

## 最超出时间预期的环节

验收路径和目录布局对齐花的时间最超预期。原本以为代码写完、本地测试通过就能收尾，后续评分器扫描仍然报文件找不到。排查后发现，课程下发目录去掉了 starter/，但评分器仍按原布局找文件。这让我意识到，“功能通过测试”与“验收工具能在交付目录正确运行”都需要证据。

## 上生产最不放心的部分

我最不放心 FLOOR 拦截在真实环境中是否真的生效。本地可以证明修改风险表后提交仍被拒，但真实系统的部署位置、访问权限和审批服务配置是否保证 Agent 无法绕过，需要实际验证。目前没有真实环境证据，我不会把本地 mock 的通过结果当作生产就绪证明。

## Agent 协作中我必须把关的内容

主要实现工作由 Agent 完成。我必须理解和把关的是安全边界与权限管理：身份从平台令牌取得，不能接受请求体自报身份；调用只能落在允许的能力与站点内；草稿和提交的风险不同，口头承诺不是审批凭证；未知数据不能补成零，响应丢失不能直接重试；宿主自由文本作为数据隔离，不能改变执行权限。即使代码和测试主要由 Agent 编写，我仍需判断这些约束是否与需求一致，以及证据能证明到哪一层。
